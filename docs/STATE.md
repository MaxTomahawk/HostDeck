# Durable state services

`StateServices` is the local persistence adapter for the stable job, artifact, device, event, diagnostics and artifact-apply operations. The caller must pass an authenticated context produced by the facade (`ownerId`, `deviceId`, `executorId`); caller arguments never establish ownership. The installer must place `root` in protected state and provide a designated user shell/executor. The preferred `desktopWorkerExecutable` option uses the Windows worker's detached Job Object runner; without it the tested PowerShell fallback reports descendant uncertainty on cancellation/timeout.

State is stored in SQLite through Node's built-in `node:sqlite`. Jobs and owner-scoped artifact manifests are journaled before/after effects; requests are idempotent per owner/device/executor and a changed digest conflicts. A separate random key under the protected state root HMACs the argument digest; the job journal stores the digest, not the raw command. Runner requests and receipts live in the protected state directory. Startup and reads reconcile only the exact receipt path for a job; an absent receipt leaves accepted/running work unchanged, and arbitrary commands are never replayed. The native Windows runner test covers service-state reopen, output/exit receipts, cancellation and timeout with descendant containment.

Artifact reads are bounded to 1 MiB per call and include a SHA-256 digest; manifests expire after seven days and the default owner quota is 256 MiB. `storeArtifact` and `artifactBytes` provide owner-scoped integrity-checked helpers for gateway captures. `apply_artifact` returns a staged `{destination, bytes, mimeType}` result for the gateway to authorize and commit. Diagnostic output contains only device health, timestamp and optional job identifiers/status/timestamps. Events are sequence ordered and retained to 10,000 records. The state directory and its SQLite/WAL/runner files contain sensitive user data and require installer ACLs and retention policy.

Focused local check: `node --import tsx --test test/hostdeck-state.test.ts`. The local Windows run exercised PowerShell and the built native worker. Other platforms can exercise persistence and authorization only.
