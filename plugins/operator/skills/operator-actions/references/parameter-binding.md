# Typed parameters and protected input

1. Author field names, types, constraints and reviewed instructions without secret values.
2. Read the action's current parameter schema. Bind nonsecret values only into allowed typed properties or argument positions; do not turn user text into unbounded shell syntax.
3. Use the returned plan and step version for preview and execution. A task claim, caller-provided context or remembered action contract cannot override the server's current binding.
4. Declare required secret fields, then direct the person to the existing protected portal control. Never place secrets in chat, tool arguments, URLs, command text, comments, screenshots or evidence.
5. Inspect the sanitized execution receipt and verify the intended effect. Keep raw provider credentials and unnecessary sensitive output outside coordination records.

Discover the actual placeholder/binding format instead of treating an illustrative template as API syntax. The server owns the permitted target, identity, parameters and operations. A displayed command remains instructions until an already registered action is bound and separately authorized.
