# HostDeck MCP App management panel

`index.html`, the bundled `app.js`, and `styles.css` are served as the `ui://hostdeck/management` MCP App and by the standalone same-origin `/ui` route. Rebuild `app.js` from `app.ts` with `npx esbuild ui/newtree/app.ts --bundle --format=esm --platform=browser --outfile=ui/newtree/app.js` after changing the source. MCP Apps use the official `@modelcontextprotocol/ext-apps` `App` and `PostMessageTransport`; standalone mode uses the official MCP SDK Streamable HTTP client and an in-memory short-lived bearer token. Both paths show actual server responses, require an authorized device ID, and keep untrusted tool output in text nodes.

## B007 extension manager

- `app.ts` mounts the manager from `extension-manager.ts` into the existing `Providers` view (now labelled Extensions). The existing OAuth/MCP App transports and files/jobs/terminal/screen/overview routes remain unchanged.
- `extension-catalog-data.ts` contains all 79 public-safe research candidates from the pinned B005/B007 sources, including their research category and upstream version/licensing hints. It contains **no local installed/runtime evidence or user configuration**. Do not label a candidate qualified or installed because it is listed.
- `extension-catalog.ts` combines immutable catalogue identity with **only** a current authenticated `hostdeck_list_providers` snapshot for direct/Everything, preserving unknown versus negative and the separate installed/enabled/running/on-demand/compatible/healthy/selected/qualified axes.
- The only supported mutating manager action is `hostdeck_set_provider_preference` for `files.name` (direct/Everything) or `files.content` (direct). The page does a preflight preference read, sends one action, then reads back; because no backend CAS/version field exists, this is a **best-effort conflict check**, not an atomic revision guarantee. Unknown effect must not be automatically retried. A future backend CAS operation needs a separately approved contract change.
- The 79 candidates have no general install/start/stop/configure/update/repair/rollback action; the UI explains unsupported lifecycle and never shows a working-looking button for it. Current changes are a page-local receipt summary, not a durable backend journal.
- Browser filtering/search/grouping is local-only and does not trigger a filesystem scan. Candidate capability hints are labelled research hints; only current HostDeck provider capabilities are called actual.
- **Build gate:** `npm run build:hostdeck` rebuilds the generated `ui/newtree/app.js` from `app.ts` via `scripts/build-hostdeck-ui.mjs`; the checked-in bundle in this delegated source branch has not been generated or validated. Codex must rebuild and run the focused tests before installing/accepting this UI.
- **Focused tests:** `node --import tsx --test test/hostdeck-manager-catalog.test.ts test/hostdeck-ui.test.ts`. The browser portion requires `HOSTDECK_TEST_BROWSER_EXECUTABLE`; otherwise it reports skipped. The tests are code proposals until actually executed.
