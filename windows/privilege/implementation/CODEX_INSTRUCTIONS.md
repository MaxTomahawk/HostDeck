# Agent instructions — every new Codex/ChatGPT session

**Read** `HANDOFF.md`, `docs/SECURITY_BOUNDARY.md`, `docs/VALIDATION.md` and the current HostDeck `docs/NEXT_RUN.md` before using this privilege route. The broker is NOT proof of an active delegation until a Windows acceptance report exists. Do not install or modify Windows without an explicit implementation mandate.

1. **Scope:** read the latest user request and decide the *goal* and permitted outcomes. Don't infer the power to remove data, destroy security controls, change networks, reset accounts, expose secrets or publish external ingress merely because an agent has a SYSTEM task available. Ordinary routine maintenance within clear goals may use general Windows admin without per-command UAC; unclear/irreversible/large consequences require an explicit bundled *goal* confirmation from the human.
2. **Use least power:** prefer ordinary unelevated commands when possible. Use this broker only for the steps that actually require elevation. Never try to route UAC Secure Desktop around HostDeck UI automation or instruct a tool to click consent dialogs.
3. **Before submission:** prepare exact script in a private local path, preview expected state changes, record goal, originating user instruction/message, reason elevated rights are necessary, risk (`standard` / `elevated-risk` / `critical`), expected effect, safe rollback idea, optional project/chat ID, and goal/retry ID. Do not include passwords, tokens, API keys or other secrets in script content that enters chat or audit metadata; use approved secret stores on the target host.
4. **Human authorisation:** obtain one bundled goal-scoped confirmation when the existing mandate is inadequate. For `critical`, attach independent owner-signed `Approve-Goal.ps1` artifact after user approval. This cannot be self-issued by an agent possessing only the client signing key. For routine requests, cryptographic verification proves possession of the standing delegated client key, **not** correctness of the user's natural-language mandate.
5. **Submit:** use the installed `public/Submit-AdminRequest.ps1` from the **enrolled client SID** and correct CurrentUser key. Do not run an elevated agent shell persistently; treat per-request scripts as separate elevated actions. Do not copy keys to another account or ChatGPT.
6. **Result:** inspect the request-specific outbox receipt and protected audit (via authorized auditor). `completed-unverified-effect` means only that the native runner returned zero; independently inspect the exact target. Log actual observed change and relate it to request ID. If uncertain or failed, inspect before retry; never blind-replay an elevated command that might have partly executed.
7. **Continuity:** reuse the registered broker across new chats/logins/reboots. New chat should discover the persisted status, not silently re-enroll. The chat itself is not a grant; only the enrolled key/HostDeck auth is.
8. **Stop conditions:** user revokes, unknown client identity, missing audit, invalid task/ACL, tampered runner, unresolved intent, absent owner approval for declared critical goal, or remote `host:manage` grant missing → do not execute. Don't broaden permissions to bypass a failure.

No action-catalog maintenance; new Windows admin scripts are supported through the generic signed request path. **A model's self-assessed risk is not an independently enforceable risk classifier.** Real end-to-end tests remain required.
